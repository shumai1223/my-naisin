# T-PV5 UI刷新後の回遊・ツール利用の低下を、原因別に切り分ける（報告が中心）

- 起票: 2026-11-06（👤が「夜に回す」と決定）。
- 背景（実測・週次測定 11/02と11/06の追記）:
  - PV/日 491 → 454〜457（−8%）、ページRPM 164 → 154（−6%）。
  - ツール利用（ユーザーあたり）: 計算完了 33%（10/1〜15）→ 21%（10/20〜29）→ 16%。直近はほぼ横ばいで下げ止まり。
  - 着地が総合得点・S値ページへ移った影響が混ざる、と記録されている。UI刷新（10/16）の前後比較は `ops/baselines/ui-redesign-2026-10/baseline.md`。
- 目的: 低下が**UI刷新によるもの**か、**着地ページの変化**か、**季節・外部要因**かを分け、直せるものだけを提案する。

## 先に読む制約（破らない）

- **UIは変えない**（👤の指示）。見た目・レイアウト・導線の変更は提案までで、実装しない。
- 実験・A/Bはしない。報告のみ。値を直前の施策の効果と結びつけない（反映に1〜3週間のラグ）。
- GA4は同意者のみの参考値（GSCクリックの約10〜19%）。転換の真値はD1/LINE、規模はGSC。GA4のゼロをアラートに使わない。
- 個人情報は記録しない。

## 作業項目（上から）

- [ ] E-1 **着地ページ別の分解**: GSCのクリックを着地ページ別に、10/1〜10/15（刷新前）と10/20〜11/5（刷新後）で比べる。ツール利用率の低下が、着地ページの構成変化（総合得点・S値の比率増）でどこまで説明できるかを、ページ別のツール利用率で出す。
- [ ] E-2 **同一ページ内の前後比較**: 刷新前後でページ構成が同じ主要ページ（トップ・/hensachi・県別内申点）について、ツール開始率・計算完了率を比べる。着地ページ変化の影響を除いた、UIそのものの影響の上限を出す。
- [ ] E-3 **端末別（スマホ63%・PC33%）の切り分け**: ツール利用率とRPMを端末別に分解。スマホの広告視認率の低下（約56〜58% → 約52%）との関係を記録。
- [ ] E-4 **計測の欠落の確認**: 刷新でイベント（tool_start・tool_complete・result_view）の発火が落ちていないか、コードとGA4の日別件数の両方で確認する。計測の欠落なら、これはUI変更ではなく修正。
- [ ] E-5 **提案を3つまで**: 直す価値があるものを、効果の見立て（根拠つき）・工数・UIを変えるか否かで並べる。UIを変えるものは「提案のみ・👤判断」と書く。
- [ ] E-6 **結果を `ops/baselines/weekly/` の次回の週次に反映**: 11/9（月）分の記録に、E-1〜E-5の要点を入れる（T-WK1との重複を避け、リンクで参照）。
