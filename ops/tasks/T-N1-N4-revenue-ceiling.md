# T-N1: 入試データの年次変化レポート（★最重要・正確性が生命線）

## ⚠️ まず認めるべき事実（2026-08-30に実測で判明）

```
倍率の多年度データ  → 47/47県 ✅ 持っている
制度の多年度データ  → ❌ 持っていない
source-history.ts の90スナップショット → 全て2026-07/08取得
  = 「いつ取ったか」の記録であって「去年何だったか」ではない
```

**したがって、いま「制度変更レポート」は作れない。** これを直視した上で設計する。

## ★N1-0: 正確性の設計（これを最初に決める。実装より先）

**「47県の変更を網羅した」は、証明不可能な主張である。**
1件でも漏らせば嘘になり、**サイト全体の信頼（Y-0の堀）まで巻き添えで死ぬ。**

→ **網羅を主張しない。検証可能性で売る。**

| 主張しないこと | 代わりに主張すること |
|---|---|
| ❌「47県すべての変更を網羅しました」 | ✅「**各項目に前年度と今年度の出典URLを付けています。30秒で検証できます**」 |
| ❌「漏れはありません」 | ✅「**検出方法を公開します。この方法で拾えない範囲も明記します**」 |

**これは `Y-0憲法`（公表値のみ・学校別偏差値は推定しない）と全く同じ構造の判断である。**
「持っていないものを持っていると言わない」ことが、この事業の唯一の差別化なので、商品でも同じ線を引く。

### 実装する正確性の仕組み（3層）

- [ ] **① 1差分1出典**: 検出した変更すべてに「前年度の出典URL＋今年度の出典URL＋該当箇所」を付ける
- [ ] **② 二重確認**: 機械が検出 → **別イテレーションで一次ソースを開いて人間可読の形で再確認**。
      「機械が検出した」と「一次ソースで確認した」を**別フィールドで記録**する
- [ ] **③ 不変条件テスト**: 差分がありえない値になっていないか
      （満点が突然1000点になる／評定が6段階になる／県数が48になる 等）
- [ ] **④ 検出できない範囲の明記**: PDF画像のみの県・Waybackに無い県は**「未確認」と正直に書く**

⚠️ **③と④を省いたら、この商品を出してはいけない。**
