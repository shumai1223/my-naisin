# T-Y14 学校・学科別「入学者選抜の評価方法」DB（47都道府県×学校×学科）

- 起票: 2026-09-15（👤指示・Discord運用セッション） / 実行主体: loop単独（対外送信・env・D1操作なし）
- 優先度: **最優先（👤指示により即着手）**

## なぜやるのか

既存の `src/lib/prefecture-exam-data.ts`（`ExamRatioConfig`）や `src/lib/total-score/*` は
**都道府県レベルの総合得点方式**（例: 東京1020点満点、神奈川S値方式）のみを実装済み。

しかし実際の選抜は**学校・学科ごとに**評価方法が異なる場合がある:

- 学力検査と調査書点の比重を学校・学科単位で変えている県（傾斜配点）
- 特定教科（実技系・英語等）を学校・学科単位で加重している場合
- 面接・実技検査・作文・自己表現・小論文等の実施有無と配点は学科（専門学科/総合学科等）で異なる
- 特色選抜・推薦選抜の実施可否・選抜方法も学校・学科単位

**県レベルの計算式だけでは「その学校のその学科は実際どう評価されるか」に答えられない。**
これは既存の `competition-rates/`（学校別倍率）・`exam-schedules/`（日程）と並ぶ
「学校・学科粒度データ」の欠けているピースであり、TIER Y（学校マスターDB）の一部として扱う。

## Y-0憲章の適用（★通常のY系タスクより一段慎重に）

- **公表値のみを転記する。独自推定は一切しない**（配点比率・実施有無を教委の「入学者選抜実施要項」
  「選抜・評価方法一覧」等の一次資料からそのまま転記する。行間を読んで推測しない）
- **1データ点1出典**（都道府県教育委員会が公表する実施要項PDF・学校別一覧のURL必須）
- **これは「評価方法（ルール）」のDBであり、「偏差値」「合格ボーダー」ではない。**
  Y-0が禁じる「学校別の偏差値・合格ボーダーの独自推定」には該当しないと判断するが、
  作業中に「この学校は難易度が高いからボーダーが上がる」等の**推定的な記述が1文字でも
  混入しそうになったら即座に手を止め、質問ノートに書いて👤の裁定を仰ぐこと**
  （評価方法＝ルールの転記と、難易度＝結果の推定は別物であることを常に区別する）
- 年度で改定されるため `fiscalYear` ごとに別レコードとして持つ（既存Y系と同型）
- 確認できない学校・学科は `unknown` と明示。空欄放置・推測禁止

## ★★ 着手前ゲート（半日・まずこれ）

人口規模・制度が異なる3県（例: 東京・大阪・秋田など）で実際に一次資料（入学者選抜実施要項、
または学校別選抜方法一覧PDF）を確認し、**「学校・学科ごとの評価方法が構造化された一覧として
公表されているか」**を判定する。

- 判定観点: 県教委サイトに「学校別選抜方法一覧」のような**表形式の一次資料**があるか、
  それとも各学校の募集要項を1校ずつ開かないと分からないか（後者なら47都道府県×数百校の
  収集コストが T-Y11B/T-Y13 と同等以上になる可能性が高い）
- **2/3県以上で県単位の構造化一覧（一覧PDF等）が見つかれば続行**
- 見つからなければ「学校単位の巡回コストが47都道府県で見合わない」と判断し、
  質問ノートに実測結果を書いて主食を差し替える

## 対象とするデータ項目

1. 学力検査：調査書点の比重（学校・学科単位で県標準と異なる場合のみ記録。県標準と同一なら
   「県標準どおり」と明記し重複データを作らない）
2. 傾斜配点の有無・内容（特定教科の重点化等）
3. 面接・実技検査・作文・自己表現・小論文等の実施有無（学科単位）
4. 推薦選抜・特色選抜の実施有無と選抜方法概要

## 設計（新規実装）

- `src/lib/school-selection-method/`: 型（`SchoolSelectionMethod` 等）と純関数
- `src/data/school-selection-methods/<pref>.ts`: 県ごとのデータファイル
  （`competition-rates/` `shien-uwanose/` と同じ配置方式）
- 既存 `prefecture-exam-data.ts`（県レベル計算式）とは**独立した別レイヤー**として実装し、
  既存の総合得点計算ロジックを一切変更しない（後方互換）

## 作業の順序

1. 着手前ゲート（3県）
2. 通過後、県単位で「学校・学科別評価方法の構造化一覧が存在するか」を47県分探索し台帳化
3. 「あり」の県から学校・学科別データを実装
4. 表示（新規ページ or 既存ページへの追記）は👤判断。このタスクはデータ層までがスコープ

## 守ること

- 対外送信・env変更・Stripe・D1破壊的操作は無し
- 学校名は公表資料に載っている校名の転記のみ（個人名・住所等PIIは記録しない）
- 既存の総合得点計算・学校ページの表示結果を上書きしない
