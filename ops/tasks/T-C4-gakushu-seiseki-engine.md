## 1. ★確定した定義（一次ソース・これ以外を実装してはいけない）

**出典**: 文部科学省「令和４年度大学入学者選抜実施要項について（通知）」
３文科高第２８４号（令和３年６月４日）**別紙様式１「調査書記入上の注意事項等について」**
https://www.mext.go.jp/content/20210604-mxt_daigakuc02-000005144_1_1.pdf

⚠️ **loopは実装前に、この一次ソースの最新年度版を必ず自分で取得し直し、下記の定義が変わっていないか確認すること。**
確認できた年度と取得日を `src/lib/source-history.ts` に登録する。

### 1-1. 各教科の学習成績の状況

> 「各教科の学習成績の状況は，指導要録に基づき，**各教科ごとに各科目の評定の合計数を各教科の評定数で除した数値（小数点以下第２位を四捨五入）**を記入すること」

**公式の計算例（テストに必ず入れる）**:
理科＝物理基礎3・化学基礎3・生物基礎5 → (3+3+5)÷3 = 3.66 → **3.7**

### 1-2. 全体の学習成績の状況

> 「全体の学習成績の状況は，指導要録に基づき，**すべての教科・科目の評定の合計数をすべての評定数で除した数値（小数点以下第２位を四捨五入）**を記入すること」

**公式の計算例（テストに必ず入れる）**: 120 ÷ 31 = 3.87 → **3.9**

### 1-3. ★単位数で重み付けしない（最重要・差別化点）

公式の計算例では、**国語総合（4単位）も保健（2単位）も家庭総合（4単位）も、すべて「評定数1」として数えている。**
調査書には「修得単位数」の欄が存在するが、**学習成績の状況の計算式には一切入らない。**

→ **APIもUIも、単位数を受け取らない。** 型レベルで受け取れないようにして、誤りを構造的に不可能にする。
→ **これを間違えている解説サイトが多い。出典付きで正しく実装することが堀になる。**

### 1-4. 複数学年にわたる科目

> 「（注）保健体育のように，複数学年にわたって履修する科目については，**各学年ごとの評定数をそれぞれ１科目分として取り扱い**計算すること」

例: 体育（1年4・2年3・3年4）＋保健（1年4・2年5）＝ 評定数5、合計20

### 1-5. 学習成績概評

対象は「**３か年間における全体の学習成績の状況**」。

| 全体の学習成績の状況 | 学習成績概評 |
|---|---|
| 5.0 〜 4.3 | **A** |
| 4.2 〜 3.5 | **B** |
| 3.4 〜 2.7 | **C** |
| 2.6 〜 1.9 | **D** |
| 1.8 以下 | **E** |

> 「大学が希望する場合，学習成績概評Ａに属する生徒のうち，人物，学力ともに特に優秀な者については，
> 「学習成績概評」の欄にⒶと標示することができる」

→ Ⓐは**高等学校長が付けるもので、計算では出せない。** UIで「Ⓐは学校が付与するため当ツールでは算出しません」と明記する。

### 1-6. ★正式名称は「学習成績の状況」

**この通知に「評定平均」という語は1度も出てこない。** 正式名称は「学習成績の状況」。
「評定平均（値）」は旧称・通称。

→ **SEOは「評定平均」で取り、本文で「文科省の正式名称は学習成績の状況」と出典付きで説明する。**
これはE-E-A-Tの直接の材料になる（他サイトが書けない）。

## 2. 作るもの

### A. 計算エンジン（純関数）— `src/lib/gakushu-seiseki.ts`

```
type Hyotei = 1 | 2 | 3 | 4 | 5;
type Kamoku = { kyoka: string; kamoku: string; gakunen: 1|2|3|4; hyotei: Hyotei };
```

- `calcKyokaStatus(kamoku: Kamoku[]): Record<kyoka, number>` — 教科ごと
- `calcOverallStatus(kamoku: Kamoku[]): number` — 全体
- `toGaihyou(overall: number): 'A'|'B'|'C'|'D'|'E'`
- 端数処理は **小数点以下第2位を四捨五入 = 小数第1位まで**。共通関数にして両方で使う
- **`tanni`（単位数）というフィールドを型に持たせない。** 受け取れないようにする

⚠️ 浮動小数の四捨五入は誤差が出る（3.45が3.4になる等）。**丸め方を1箇所に閉じ、境界値のテストを厚く書く。**

## 7. ★「ほかにないページ」を作る（👤指示 2026-08-27）

> 「極めて使いやすい、ほかにないページを数個でも作らせるようにしてね。専門的な一面もある」

**§2-B の1枚では足りない。下記5枚を作る。** すべて §1 の一次ソースだけから導ける（推定値を一切使わない）。
**共通の設計原則: 入力は最小、出力は調査書と同じ言葉、根拠は必ず出典付き。**

### ① 調査書シミュレーター — `/chousasho`（★これが本命）

**調査書 様式１の「２.各教科・科目等の学習の記録」「３.各教科の学習成績の状況」「４.学習成績概評」を、実際の様式そのままの見た目で再現する。**

- 科目を入力すると、**先生が書く調査書と同じレイアウト**で埋まっていく
- 教科ごとの学習成績の状況 → 全体 → 概評A〜E が、様式の並び順で出る
- 「あなたの調査書はこう書かれます」という体験になる

**なぜ他に無いか**: 他サイトは「数字を1つ出す」だけ。**調査書という書類そのものを見せているところが無い。**
生徒は調査書を自分で見られない（開示請求は可能だが実質見ない）。**中身が初めて可視化される。**

⚠️ 単位数欄は様式には表示するが、**計算には使わないことを画面上で明示する**（§1-3）。

### ② 教科別の学習成績の状況 — `/chousasho/kyoka-betsu`

大学の出願基準には「**英語の学習成績の状況4.0以上**」「**数学および理科の学習成績の状況3.8以上**」型が実在する。
しかし**教科ごとの数値を出せる計算機がほぼ無い**（全体しか出さない）。

- 教科を選ぶと、その教科だけの学習成績の状況を出す
- 文科省の公式計算例（理科 3.66→3.7）をそのまま検算できる形で置く

**⚠️ 具体的な大学名と基準値は載せない**（推定値になるため・§4）。「こういう形式の基準がある」までに留める。

### ③ 概評の境界までの距離 — `/chousasho/gaihyou`

**いちばん実用的な1枚。**

- 現在の全体の学習成績の状況を入れると、**いまA〜Eのどれか**、そして
- **1つ上の段階まであと何点必要か**（例: 3.4 → Bまで0.1）
- **残りの科目数を入れると「残りで平均いくつ必要か」**（`/gyakusan` の資産をそのまま使う）

**なぜ効くか**: 概評は**境界で1段階変わる**。3.4と3.5では書類上の意味が違う。
**自分が境界のどちら側にいるかを知りたい需要は確実にある。**

### ④-0 ⚠️「文科省の公式計算例(120÷31)そのもの」は使わず自作の具体例に変更した（2026-08-28・loop実装時判断）

省略された抜粋例であり、単位数・学年の内訳を含む31件のフル明細は通知のどこにも記載されていない**
と判明した（一部の科目・評定・単位数は例示として掲載されているが、31件全体には届かない）。

（通知の計算ルールには完全準拠・出典は明記）で実演する**方針に変更した。文科省の公式計算例

### ④ ★「よくある3つの誤り」検証ページ — `/chousasho/yokuaru-machigai`（★専門性の核）

**文科省の公式計算例（全体 120÷31=3.87→3.9）を使い、誤った方法だと数字がいくつズレるかを実演する。**

| よくある誤り | なぜ誤りか（出典） | 公式例だといくつになるか |
|---|---|---|
| **単位数で重み付けする** | 通知の計算例は4単位も2単位も「評定数1」として数えている | ← loopが実際に計算して載せる |
| **教科ごとの平均をさらに平均する** | 全体は「すべての評定の合計÷すべての評定数」であり、教科平均の平均ではない | ← 同上 |
| **3年生の成績だけで計算する** | 概評は「**３か年間**における全体の学習成績の状況」 | ← 同上 |

### 5枚に共通して守ること

1. **入力を最小にする。** 科目を1つずつ入れるのが苦痛なら誰も使わない。
   → 学年ごとの一括入力・よくある教育課程のテンプレ・前の入力の保持（localStorage）を検討する
2. **出力は調査書と同じ言葉を使う。**「評定平均」ではなく「**学習成績の状況**」を主、「評定平均」を併記
3. **すべての数値主張に出典を付ける。** §1 の文科省通知のURLと該当箇所
4. **推定値を1つも置かない。** 大学別の基準値は §4 のとおり載せない
5. **相互に繋ぐ。** ①→②③④⑤ へ回遊できるようにする
6. **個人情報を受け取らない**（§3）。localStorage は端末内に留まる旨を明記
