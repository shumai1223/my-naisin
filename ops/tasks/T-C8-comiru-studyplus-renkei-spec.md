## 1. なぜComiru・Studyplusなのか（1行）

Comiru（保護者が通知表・内申点を入力する機能を既に持つ）・Studyplus for School（連携APIを公開し
教材ベンダーと連携実績あり）の両方とも「学習記録はあるが、内申点の47都道府県方式換算と志望校の
公表倍率が無い」——そこに1対1で嵌まる（詳細は`ops/prompts/fable-revenue-challenge-2026-09-03-ANSWER.md`）。

## 2. 提供できるもの（3つの接続方式・先方の実装コストが低い順）

### 方式A: 埋め込みウィジェット（最短・フロントエンドに1行）

| ウィジェット | URL | 機能 |
|---|---|---|
| 内申点計算 | `https://my-naishin.com/embed/naishin` | 9教科評定→47都道府県方式の内申点（調査書点） |
| 偏差値計算 | `https://my-naishin.com/embed/hensachi` | 得点・順位から偏差値を算出 |
| 学習成績の状況 | `https://my-naishin.com/embed/gakushu-seiseki` | 調査書「学習成績の状況」の評定平均・概評 |

- 実装は`<iframe>`1行（scriptタグ埋め込みも可）
- クレジット表記はサーバー側HTMLに焼き込み済みで外せない（`embed-routes.test.ts`で固定）
- 埋め込み先ドメインを`?domains=`クエリで軽量制限可能（正式なAPIキー紐付けは契約後に拡張）
- 汎用モックのデモ: `https://my-naishin.com/embed/demo`（noindex・特定企業の画面を複製しない
  一般化レイアウトの中で実際に動くウィジェットを見せる。**先方専用のモックアップが必要なら
  AA-2のベネッセ向けモックアップ〈`ops/tasks/AA-2-embed-demo-mockup.html`〉と同じ方式で
  Comiru/Studyplus向けにも個別に作成可能**——ロゴ・実画面は複製せず「〇〇管理画面（イメージ）」
  という一般化した体裁のみ）

### 方式B: REST API（先方サーバー側から取得・自社UIに独自表示したい場合）

主なエンドポイント（全量は`https://my-naishin.com/api/openapi`のOpenAPI仕様を参照）:

| エンドポイント | 内容 |
|---|---|
| `POST /api/naishin` / `/api/naishin/{code}` | 内申点計算（47都道府県一括 or 1県指定） |
| `GET /api/schools/{pref}` | 都道府県別・学校×学科ごとの募集人員・応募者数・倍率（複数年度） |
| `GET /api/total-score/{code}` | 総合得点方式（東京1020点・神奈川S値等）の計算 |
| `GET /api/hensachi` / `/api/gakushu-seiseki` | 偏差値・学習成績の状況の計算API版 |
| `GET /api/naishin/csv` | 内申点の正準データをCSV配布 |

- キー認証（`/api/keys`で発行）・ティアごとのレート制限/月次クォータは`/api/openapi`参照
- 学校別入試競争率（`/api/schools/{pref}`）は無償公開APIでは非公開・Business以上のキーが必要
  （後述「4. 想定料金」参照）

### 方式C: MCP（AIアシスタント経由・PRサイド向け）

`https://my-naishin.com/api/mcp`でMCPサーバーとして内申点計算・都道府県比較・逆算ツールを提供済み
（`list_prefectures`/`get_prefecture`/`calculate_naishin`/`compare_prefectures`/`reverse_calc`等）。
先方が生成AI機能（学習アドバイザーAI等）を持つ場合、ツールとしてそのまま組み込める。

## 3. データの性質（Y-0を先方にもそのまま開示する）

- 学校別の偏差値・合格ボーダーの推定値は一切含まない。教育委員会の公表値（募集人員・応募者数・
  倍率）と公式の計算方式のみ
- 47都道府県対応・複数年度（令和7・8年度、県により令和4〜6年度も収録）
- 学校別入試競争率は3,260校・21,548件（配布可能分。詳細は`ops/deliverables/obunsha-poc-v0/
  format-spec.md`と同じデータ基盤を使用）
- 氏名・学籍番号等の個人情報は受け取らない設計（型定義レベルで保証。計算はブラウザ/サーバー
  完結でPIIを保存しない）
