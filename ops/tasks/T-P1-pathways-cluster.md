## 🔴 P1-0 設計の前提を変更（2026-09-03・Fable 5.1の指摘と対話セッションの検算による）

**このクラスタを「記事」として作ってはいけない。「ツール」として作ること。**

### 根拠（実測・GSC 28日窓・1,000クエリ）

3位以内かつ5クリック以上を獲得しているクエリは25本。**そのうち24本が計算機面だった。**

```
140click 順位2.3  高校偏差値 診断            → /hensachi
 37click 順位1.1  都立高校 総合得点 計算 サイト → /tokyo/total-score
 36click 順位2.0  s値 計算                  → 神奈川 total-score
 16click 順位2.1  中学生 偏差値 診断          → /hensachi
 10click 順位1.4  評定平均 自動計算 中学生     → /hyotei-heikin
  …（24本すべてが「利用者が操作する面」）

  8click 順位2.0  三重高校   ← ★唯一の非計算機面。1,273表示でCTR 0.63%
```

**このサイトが上位で кликを取れているのは、例外なく「利用者が何かを入力して答えが返る面」だけ。**
情報を並べた面（学校ページ・ブログ）は順位が取れてもクリックされない。
`三重高校` は2位で1,273表示ありながらCTR0.63%で、その最も明確な標本になっている。

### したがって

- ❌ **「不登校でも行ける高校の制度解説」という記事群を作らない。** 作っても同じ結果になる
- ✅ **入力して答えが返る面にする。** 例:「いまの内申点・出席日数を入れると、
      **制度上どの選抜枠が公表されているか**が県別に返る」
- ⚠️ ただし返すのは**制度の該当可否だけ**。「あなたはここへ行くべき」は絶対に書かない（Y-0）
- ⚠️ 合否可能性・偏差値・ボーダーは返さない。返すのは**公表されている枠の存在と要件**のみ

**P1-3（公立定時制・通信制のデータ化）は、この面に入れるデータとして必要。順序は変わらない。
変わるのは出口が記事かツールかだけ。**

### ★反証条件（作業前に固定・2026-09-03）

**ツールとして成立するかどうかは、P1-3の収集が終わった時点で判定する。**

```

          ＝ 定員・倍率・出願要件のいずれかを、公表値として県別に返せる県

10県以上  → ツールとして作る（出口確定）
10県未満  → ★ツールにしない。実態は記事と同じになる
            その場合は👤に上げて、続けるか止めるかを判断してもらう
```

⚠️ **「10県に届かなかったから基準を8県に下げる」をやらない。** 届かないなら、
このクラスタは記事にしかならず、記事は効かないことが実測で分かっている。
**そのときは止めるのが正しい。**

⚠️ 数を作るために「制度の説明文だけあって数値が無い県」を県数に数えない。
