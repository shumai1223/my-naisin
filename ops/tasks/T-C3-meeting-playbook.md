> 「B2B（API・MCP・DBの交渉など）にすべてを捧げる。B2Bをやって損をすることはない。

**負担が「商談をこなす能力」だと本人が特定している以上、そこを機械で埋めるのが loop の仕事。**

さらに 2027年度以降は「ほぼ不労状態で回る」ことを目標に置いている（高校・部活・受験と並走するため）。
**商談で学んだことを、商談を要らなくする資料に変換していく**のが最終形（S13-A A-6 に合流する）。

## やること

### C3-1 ベネッセ商談の振り返りを言語化して型にする

Gmail の当該スレッド（送信済み 2026-07-22）を読み、以下を1ファイルに落とす。

- 相手が言った**課題の言葉そのもの**（言い換えない。営業文面はこの言葉を使う）
- こちらが答えられなかった質問／詰まった箇所
- 次に同じ質問が来たときの答え

⚠️ **個人名・所属は書かない（PII・C7）。** 「大手通信教育の担当者」等の粒度にする。

### C3-2 想定問答集を作る（B2Bライセンス商談用）

最低この10問には即答できる状態にする。**答えは実データで裏を取る（憶測を書かない）。**

1. データはどこから取っているのか（→ 47都道府県教委の公表資料。一次ソースURLを即出せるか）
2. 更新はどうなるのか（→ 年次更新の体制。T-A1 多年度化の実績）
3. 精度はどう担保しているのか（→ 不変条件テスト・jest件数・Y-0憲法）
4. 中学生が運営しているが継続性は（→ 契約主体は親権者名義。ここは正直に答える）
5. 独占はできるのか
6. 価格の根拠は（→ 自社で47県分を作る場合の工数と比較）
7. 使える形式は（→ REST API / MCP / CSV / JSON。`/developers` を見せる）
8. 商用利用の範囲は（→ 利用規約・再配布の可否）
9. 他社の導入実績は（→ **無い。無いと正直に言う。代わりに公開APIの稼働実績を出す**）
10. 試せるのか（→ 無料枠・APIキー即発行）

### C3-3 `scripts/meeting-copilot` を B2Bライセンス商談用に作り直す

**既に実装済み**（商談中のリアルタイムAI補助・即答スクリプト10種・AIサジェスト TTFB 2.7秒）。
ベネッセ商談用の `prompt.md` のまま止まっているので、C3-2 の想定問答を流し込む。

⚠️ README に「Claude Code とセッション上限を共有する」と明記されている。
**商談の数時間前から loop の重い周回は止める**運用を、👤に事前通知する仕組みも入れる。

### C3-4 稟議に出せる1枚を作る

相手の担当者が社内で使う紙。**商談の場で渡すのではなく、商談前にメールに添える。**
これがあると「持ち帰って検討します」で消えない。

- 何のデータか／どこが一次ソースか／更新体制／価格／導入方法／試用方法
- **A4 1枚**。これ以上長くしない
