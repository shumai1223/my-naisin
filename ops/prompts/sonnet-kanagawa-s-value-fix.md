## 1. 壊れている場所（実測済み・ここを見ればいい）

**`src/components/Calculator/ReverseCalculator.tsx` の `case 'kanagawa':`（217行目付近）**

```ts
case 'kanagawa':
  if (kanagawaSettings) {
    const estimatedGrade2Score = naishinNum * 0.8;   // ★欠陥1
    const sValueNaishin = (estimatedGrade2Score * kanagawaSettings.gradeMultipliers.grade2
                           + naishinNum * kanagawaSettings.gradeMultipliers.grade3);
    const kanagawaNaishinContribution = sValueNaishin * (sValueCoefficients?.academic || 0.8);  // ★欠陥3

    requiredExamScore = Math.round(kanagawaExamNeeded);

```

### 欠陥は3つある

**★欠陥1: 中2の評定を「中3の80%」と捏造している（`naishinNum * 0.8`）**
入力欄のラベルは既に **`A（評定合計）`（135点満点）** で、**Aには中2の分がもう入っている**。
それを 0.8 倍して「中2の推定値」を作り、さらに足している。**二重計上のうえに捏造。**
`kanagawaSettings.gradeMultipliers` を使う必要は最初から無い。

**★欠陥2: 100点換算を一度もしていない**
S1値は「内申135点」と「学力検査500点」を**それぞれ100点満点に換算してから**比率で合成する。
現在のコードは 135 でも 500 でも割っていないので、**単位が合っていない**。

**★欠陥3: 比率の扱いが違う**
`sValueCoefficients?.academic || 0.8` を素の乗数として掛けているが、
正しくは **f:g（合計10）** の重み。UIには既に `KANAGAWA_RATIO_PRESETS`（4:6, 3:7 等）があり、
`setNaishinRatio(ratioPercent)` で**パーセント**として保持されている（4:6 → 40）。

## 2. 正しい式（このサイト自身が公開しているもの）

**出典は自サイトの `src/app/kanagawa/s-value/page.tsx`（168行目付近）。神奈川県教育委員会の
入学者選抜情報に基づくと明記されている。勝手に別の式を持ってこないこと。**

```
a = A / 135 × 100          A = 評定合計（中2の9教科×5 ＋ 中3の9教科×5×2 = 135点満点）
b = B / 500 × 100          B = 学力検査の合計（5教科×100 = 500点満点）

S1 = a × f + b × g         f:g は学校が定める比率・f + g = 10  → S1の満点は 1000

S2 = S1 + （特色検査の素点 × 特色検査比率 i）    i は最大5・実施校のみ
```

⚠️ **`a` の式は、UIが既に画面に表示している**（`ReverseCalculator.tsx` 719行目付近に
`a値（100点換算）: {Math.round((currentNaishin / naishinMax) * 100)}` がある）。
**画面には正解が出ているのに、計算がそれを使っていない。** それが今回のバグの本質。

### 逆算（今回直すもの）

目標S1値・A・f:g が与えられたとき、必要な学力検査点 B を求める。

```
b = (S1目標 − a × f) / g
B = b × 5                  （b は100点満点、B は500点満点なので ×5）
```
