### 【修正1】Pro と Business を1問で分ける

料金ページの先頭にこの1問を置く。**これで購買担当者が自己判定できる。**

> **「あなた以外の第三者が、このデータを使いますか？」**
>
> - **いいえ**（自分で使う・社内で使う・検証する） → **Pro**
> - **はい**（自社サービスの利用者に提供する・自社商品に組み込む） → **Business**

補助基準（3つのうち1つでも当たれば Business）:

| | Pro | Business |
|---|---|---|
| 商用利用（第三者への提供） | ✕ | ✅ |
| 請求書払い・法人契約 | ✕（カードのみ） | ✅ |
| 47県データの一括取得（CSV/JSON） | ✕（API呼び出しのみ） | ✅ |
| 年次更新保証（下記の約束） | ✕ | ✅ |
| 呼び出し上限 | 10,000回/月 | 200,000回/月 |

⚠️ **「Proで商用利用したらどうなるか」も書く。** 書かないと必ず問い合わせが来る。
→ 利用規約に「商用利用が判明した場合、Business 相当額を遡って請求する場合があります」と明記。

### 【修正2】更新保証とサポートの範囲を、規約の文言として確定させる

**ここが商談ゼロの成否を決める。** 購買担当者が聞きたいことを、全部先に書いておく。
**個人（中学生）が運営していることを隠さず、約束できる範囲だけを約束する。**

| 項目 | 約束する内容 | 約束しないこと |
|---|---|---|
| **年次更新** | 各都道府県教育委員会が翌年度の入学者選抜実施要項を**公表してから60日以内**に反映する | 公表前の先行提供はしない |
| **対象範囲** | **教育委員会が公表した資料に基づく変更のみ** | 非公表の運用・学校別の内規は対象外（Y-0憲法） |
| **サポート** | メールで**平日2営業日以内**に返信 | 電話サポート・オンサイト対応は行わない |
| **稼働率** | **SLAとしての保証は行わない。** 代わりに**過去12か月の実績稼働率を公開**する | 稼働率の数値保証・違約金 |
| **障害時** | 返金・減額は行わず、**停止時間分だけ契約期間を延長**する | 逸失利益の補償 |
| **データの正確性** | 出典URLを全レコードに付与し、**第三者が検証できる状態**を維持する | 誤りゼロの保証（誤りは報告を受けてから5営業日以内に訂正） |
| **契約主体** | **親権者名義**（👤が2026-08-11に裁定済み） | — |

⚠️ **「SLAを保証しない」と書くのは弱さではない。** 個人運営で99.9%を約束して破る方が、
信頼の堀を一撃で壊す。**約束しない代わりに実績値を公開する**方が、この事業では強い。

### 【修正3】Enterprise は「基本＋オプション」に分解する

**「¥100万〜」の「〜」を消す。** 何が入っていて何が加算かを先に見せる。

**基本 ¥1,000,000/年**（Business の全内容に加えて）

- CSV / JSON の**一括納品**（月次・全47県）
- **優先サポート**（平日1営業日以内）
- **年次更新の事前通知**（公表を検知した時点で、確定前に「今年はここが変わりそう」を共有）
- 導入時の技術サポート（初回のみ・メール）

**オプション（加算）**

| オプション | 加算額 | 内容 |
|---|---|---|
| **再配布権** | **+¥500,000/年** | 自社の顧客に**データそのもの**を渡せる（＝相手が二次販売できる） |
| **DB納品** | **+¥200,000/年** | SQLite / PostgreSQL のダンプで納品 |
| **オンプレ提供** | **+¥1,000,000/年** | 自社サーバ内に設置（外部通信なし）。**理由と根拠は下記** |
| **カスタム項目** | **個別見積（¥300,000〜）** | 自社の判定ロジックに合わせた形式への変換 |

#### オンプレ提供が基本料と同額である理由（👤指摘・2026-08-13）

「+¥100万」が基本料と同額で唐突に見える、という指摘。**値段の根拠が「設置の手間」だと
誤解される書き方になっていた。実際の根拠は違う。**

**買う側がオンプレを選ぶ理由**（この3つのどれかに当てはまる企業だけが対象）:

1. **社内規定で外部APIへの通信が禁止されている**（自治体案件を持つ企業・情報システム部門が厳しい企業）
2. **止まると業務が止まる**（模試の当日処理・出願期間中の判定など、外部依存を排除したい）
3. **一括処理の規模が大きい**（数万件を一度に判定する用途では API 呼び出しが現実的でない）

**こちらが引き受けるリスク**（＝これが値段の中身）:

| リスク | 内容 |
|---|---|
| **更新を強制できなくなる** | 相手の環境に古いデータが残り続け、**誤った判定が出る**。それが「My Naishin のデータで間違えた」と言われる。信頼の堀に直接刺さる |
| **契約終了後もデータが手元に残る** | 技術的に回収できない。**実質的に永続利用に近い状態**になる |
| **提供物が別物になる** | 配布パッケージ・インストール手順・バージョン管理を新規に作り、維持する |

→ **再配布権（+¥50万）より高いのは論理的に一貫している。**
   再配布は「渡す相手が増える」だけだが、オンプレは「**渡した後こちらが何もできなくなる**」。

→ **オンプレ契約には次の条項を必須にする**（価格の正当化と、堀の防衛を兼ねる）:
   - **年次更新パッケージの受領と適用を契約上の義務とする**（古いデータでの運用を禁じる）
   - **適用しなかった場合、そのデータに起因する判定結果について当方は一切の責任を負わない**
   - 契約終了時は**データの削除証明を提出**してもらう

**営業時の説明は1行でよい**:
> 「オンプレは、こちらが更新を届けられなくなる形態なので、その分のリスクを価格に含めています」

→ 実際の提示は **¥100万（基本のみ）／¥150万（＋再配布権）／¥250万（フル）** の3点になる。
**商談で「いくらですか」と聞かれた瞬間に、この3つを即答できる状態にしておく。**

### 【修正4】独占ライセンスは、価格表に載せない

前版で「¥3,000,000〜」と書いたが、**根拠が逆算できていなかった。**

独占の値段 ＝ **想定契約社数 × 平均単価 ＋ 独占プレミアム**。
しかし **想定契約社数は実績ゼロの今、置くことができない。** ここに数字を置けば、
それは「2週間後には収益が出る」と同じ、根拠のない数字になる。

→ **独占は価格表から外し、聞かれたら「別途ご相談」と答える。**
→ **契約が3本入った時点で、実績から逆算して初めて価格を置く。**
→ ⚠️ ただし**独占を先に売ってはいけない**。1社に独占を売ると、残り322社への道が全部閉じる。
   独占の話が出たら、それは**その相手が本気である最良のシグナル**なので、👤に即エスカレーションする。

### 【修正5】Business を ¥240,000/年 にする理由

👤の提示は「25〜30万・根拠を明確に」。その範囲内で **¥240,000（月2万円ちょうど）** を推す。

1. **稟議で「月2万円」と言える。** 年額より月額換算の方が社内を通りやすい。
   ¥298,000 だと「月24,833円」で説明が濁る
2. **¥300,000 は課長決裁の上限に置かれていることが多い。** 境界ちょうどに置くと、
   審査が厳しい側に倒れるリスクがある。**¥25万未満**なら確実に下回る
3. **Pro の年額（¥117,600）のちょうど約2倍。** 「倍払えば商用利用できる」と直感的に分かる
4. **自社構築 ¥50〜190万** に対して圧倒的に安い。説明1行で優位が立つ
5. **初年度価格として提示する。** 契約書に「翌年度以降、改定する場合があります」と明記しておけば、
   実績が出てから上げられる。**値上げは既存顧客に対しては困難だが、事前に書いてあれば可能**

### 【修正6】改定のトリガーを先に決めておく（👤指摘・2026-08-13）

**「初年度価格」と書く以上、何が起きたら改定するのかを先に決めておかないと、
値上げの理由を後から作ることになる**（それは相手に必ず見抜かれる）。

⚠️ **原則: 値上げを正当化できるのは「買い手にとっての価値が上がったこと」だけ。**
「契約社数が増えたから」は**こちらの都合**であり、相手には1円の価値も無い。単独では根拠にならない。

#### 値上げのトリガー（3つのうち2つ以上を満たしたら、翌年度の**新規契約から**改定）

| # | 条件 | なぜ値上げの根拠になるか |
|---|---|---|
| 1 | **年次更新を約束どおり実行した実績が2期連続**（公表から60日以内の反映を2年） | 買い手にとっての**リスクが実測で下がった**。「本当に更新されるのか」が最大の不安だったものが消える |
| 2 | **提供範囲が契約時点より明確に拡大**（T-A1 多年度化の完了・学校別倍率の追加など） | **物が増えた**。最も分かりやすく正当 |
| 3 | **契約社数が10社を超えた** | サポート負荷の実費が上がる（**原価根拠**）。ただし**単独では使わない**（1と2のどちらかと併用） |

#### 既存契約者の扱い（ここを決めておかないと早期契約者を裏切る）

- **既存契約者は、次回更新時に旧価格を1回だけ据え置ける**（実質2年間は据え置き）
- **改定は必ず年度単位。90日前に書面で通知**
- ⚠️ **最初の3社は「創業期に賭けてくれた相手」。** 据え置き回数を増やす等の優遇を検討する余地あり
  （ここは実際に3社決まってから👤が判断する）

#### 値下げのトリガー（こちらも先に決める）

- **断り理由に「価格」が3件以上出たら見直す。** ただし「高い」と言われた回数ではなく、
  **断りメールに価格が理由として明記された件数**で数える（口頭の「検討します」は数えない）
- ⚠️ **成約0＝価格が高い、とは限らない。** 文面が悪い・相手が違う・時期が悪い方が確率は高い。
  **断られた理由を必ず聞いてから判断する**（聞かずに下げると、安いだけの商品になる）
