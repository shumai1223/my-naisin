## 1. ⛔ 停止禁止条項

**監視モードに入ってよいのは、バックログの主食が空になった時だけ。**
以下はすべて停止の理由にならない:

- 日付待ち（「11/15の窓が開くまで待つ」等）
- ゲート待ち（👤の承認待ちの項目がある）
- 👤の返信待ち
- 収穫逓減（「これ以上やっても効果が小さい」）
- 判断の迷い（「どちらが正しいか分からない」→ **質問ノートに書いて別のタスクへ進む**）
- 「区切りが良いので」

⚠️ 2026-08-02〜09 に、上記6パターン**すべて**を理由に実際に停止した前科がある。

**ただし「止まらない」と「同じタスクを回し続ける」は別物である。**
2026-08-11〜12 に、loop は T-C1 だけを150コミット以上連続で実行し、期限のある
S13-A・T-A1・T-R1 に1コミットも着手しなかった。**止まってはいないが、進んでもいなかった。**
→ **§0 の配分規則（期限ありに最低60%）を必ず適用すること。**
→ T-C1 は「手が空かないための保険」であって、**「他を後回しにしてよい理由」ではない。**

## 3. ★★ 2026-08-10〜11 に実際に起きた事故から得た教訓（最重要）

### 3-1. 「commit」「push（デプロイ）」「D1 migration適用」は**3つ別の事象**
1つ確認しただけで「本番反映済み」と書いてはならない。

**実際に起きたこと**: `trusted` 列を参照するコードがpushされたが、本番D1に migration 0019 が未適用だった。
この状態でデプロイが走ると、集計は空にフォールバックする（安全）一方で、
**`insertStatsSubmission` が毎回失敗し新規投稿が黙って捨てられる**（サイレントな計測停止）。

→ **反映確認は必ず「スキーマ」と「デプロイ済みコードの版が判別できる応答」の両方で行う。**
→ APIのレスポンス文字列が2つの版で同一になりうる場合、それは反映の証拠にならない。

### 3-2. 判定は必ず**内部referer付き**で数える
D1 `clicks` の **88%はbot**。全期間629件のうち内部パス付きrefererは**41件**しかない。

```sql
-- 人間のクリックを数える唯一の正しい方法
WHERE referer LIKE 'https://my-naishin.com/_%'
```
⚠️ `LIKE 'https://my-naishin.com%'`（アンダースコア無し）は **root_only（パス無し）まで拾う**ので使わない。
⚠️ bot込みの数で面別の勝ち負けを判定すると、**全部の結論が狂う**（実例: `fp-soudan` は記録上131クリックで
全期間2位だが、内部referer付きは**0件**）。

### 3-3. referer のパスと placement が矛盾する行は bot（内部整合性の検査）
root_only 33件のうち **21件（64%）が「そのページに存在しない placement」を名乗っていた**
（トップページから来たと主張しつつ `parent-lp` を名乗る等）。
ヒューリスティックではなく論理的な矛盾なので、**確実にbotと言える**。

→ `<AffiliateAd>` に **placement を必ず渡す**こと（現状96箇所中89箇所が未付与）。
   付けるほどこの判別軸が効く範囲が広がる。**順序に意味がある**——placement是正が先。

### 3-3b. ★ GSCの `query` / `page` 次元の合計を、サイト総計として使ってはならない

**GSCは匿名化のため、しきい値未満のクエリを次元別レスポンスから落とす。小規模サイトほど落ちる割合が大きい。**

**実際に起きたこと（2026-08-11）**: my-shingaku の28日クリックを
`query` 次元の合計から **5件**と報告したが、`gsc_totals`（次元なし）の正しい値は **52件**。
**10倍の過小報告**。しかもその誤った数字を根拠に「PLAYBOOK横展開は前提未成立」として
`ops/GRAVEYARD.md` G-5 に不採用として葬っていた（同日に判定を撤回）。

```
✅ サイト全体の規模を知りたい → mcp__gsc__gsc_totals（次元なし）
✅ 内訳・構成比を知りたい     → gsc_query の次元別（合計は総計と一致しないことを前提にする）
❌ 次元別レスポンスの合計を「サイト総計」として引用する
```
⚠️ my-naishin でも同じ乖離がある: **query次元はサイト総クリックの57%・表示の43%しか映していない**
（`ops/raw/BRIEF.md` §I）。**次元別の数字を出すときは必ず「見えている範囲の話」と明記すること。**

### 3-3c. 新規ページ・新規ドメインの順位を、現在値で評価しない

**自社実測（my-shingaku・被リンクほぼゼロの新規ドメイン）**:
```
7/13 表示   7  順位 61.3
7/22 表示 146  順位 23.6
7/31 表示 215  順位 14.5
8/08 表示 301  順位 13.9      ← 4週間で 61.3 → 13.9
```
→ **順位は固定値ではなく、露出とともに改善する。**
→ 学校ページ（公開2週間・加重9.76位）を「9.76位だからCTR1.06%」と定常状態のように語ってはいけない。
   **my-shingaku は4週間かけて14位。学校ページは既にそれより速い。**
→ **2週間のスナップショットで施策の成否を判定しない。** kill_criteria の窓は最低28日。

### 3-4. 数値を持つ型を作ったら、不変条件テストを**同時に**書く
- 2026-08-08: 満点135点の宮崎県で `avgNaishin: 425`（満点の3倍）。**3,826件のテストが全green**のまま素通り
- 2026-08-10: 偏差値の全国平均を **63.16** として本番配信（偏差値は定義上、母集団平均が50）
- 2026-08-09: 複数年度のレコードが合算され `totalQuota` が無意味な値に

**共通の原因**: ロジックのテストはあっても「その値が取りうる範囲」のテストが無かった。
例: `avgNaishin <= maxScore` / `合計 = 内訳の和` / `年額×3 = 総額` / `倍率 = 出願者数 ÷ 定員` /
`偏差値の標本平均は50±5`。

### 3-5. 公開されている記述が事実と違わないか、定期的に疑う
2026-08-10に2件見つかった: 統計API（偏差値平均63.16）と**プライバシーポリシー**（「現在、広告は掲載しておりません」と
書きながら live 34本が稼働）。**このサイトの拠り所は「公表値のみ・捏造ゼロ」なので、ここが崩れるのが最悪の事故。**

→ 機能を止めたり方針を変えたりしたら、**それを説明している公開ページも同時に直す**。

### 3-6. 「都道府県教委の入試情報ページへのリンク掲載依頼」は打ち切る（★2026-08-11 に範囲を訂正）

**実測**: 三重・石川・岐阜の3県が「引用はOK、リンクは内規で不可」と回答（2026-08・Gmail）。
3件とも理由が組織方針（「課内で協議して不可」等）なので、**この型は3/3で閉まっていると判断してよい。**

⚠️ **ただし「.jp/.go.jp からの被リンクは無理」と一般化してはならない。** 当初この憲法にそう書いたのは
**過度な一般化だった**（👤が2026-08-11に指摘）。実測は「**都道府県教委の入試情報ページ**に
**リンクを貼ってもらう**」という**単一の型**に対する3件にすぎない。

**未検証のまま残っている主体（＝まだ閉まっていない）**:
- **大学・研究室（`.ac.jp`）** — 教育学研究で内申点・倍率データを使う需要は実在しうる。DRも高い
- **市区町村の教育委員会** — 都道府県教委とは**別の判断主体**。同じ内規とは限らない
- 国立教育政策研究所・教職員支援機構 等の独立行政法人
- **公共図書館のリンク集**（伝統的にリンク集を持つ文化がある）
- 高校（`.ed.jp`）の進路指導ページ

**未検証のまま残っている「依頼の型」**:
- リンク掲載依頼以外に、**資料提供→引用される / データ提供→出典として記載される / 研究協力→論文で被引用**がある
- 三重県は**引用そのものは許諾している**（「出典を明記のうえ紹介いただくことは差し支えございません」）。
  **リンクは無理でも言及はありうる。**

**判断基準**: 被リンクは「1本の価値が桁違い × 試行コストが低い（loopが生成・👤が送信）」ため、
**成功率が低くても期待値は正**になりうる。「3件断られたから全部やめる」は誤り。
**閉まったと言ってよいのは、同じ主体・同じ型に対して複数回試して全滅した場合だけ。**
