中学3年生のしゅうまいです。高校受験の「内申点」を計算するサイト [My Naishin](https://my-naishin.com) を、2026年1月から作っています。

内申点の計算方法は、都道府県ごとにまったく違います。学年ごとの比重、実技教科の倍率、満点、学力検査との比率。同じ「オール4」でも、県が変われば点数も意味も変わります。自分の県の計算方法を調べたとき、**教育委員会のPDFを読まないと正確な答えが出ない**ことに気づいたのが始まりでした。

いまは47都道府県すべての内申点の計算方式と、42都道府県の「学校・学科ごとの選抜方法」を、各教育委員会が公表している資料だけからデータにしています。

この記事では、そのやり方を書きます。**コードの多くは、AI（Claude Code）と一緒に書きました。** 一次資料をAIに読ませると何が起きて、その間違いをどう潰したかが、この記事の中心です。

## ルールは1つ：公表されている値しか載せない

最初に決めて、いちばん大事にしているルールです。

- **教育委員会が公表している値だけを載せる**
- **推定しない**（学校別の「ボーダー」や「偏差値」は、公表されていないので載せない）
- **取れないものは「取れない」と書く**（学校別の選抜方法は、42都道府県で公表されている一覧を使いました。残る5県は学校別の一覧が公表されておらず、サイト上でも「取得できない」と表示しています）

受験生は、このサイトの数字を見て志望校を考えます。**それらしい推定値を1つでも混ぜると、ほかの正しい数字まで信じてもらえなくなります。** なので、載せないことを選んだ数字のほうが多いです。

## 一次資料はPDF。しかも県ごとに形がばらばら

教育委員会の資料は、ほとんどがPDFです。

- 縦書きで、何列にもわたる表
- 罫線のある表と、無い表
- 学区ごとに別のPDF
- 前年度から列の並びが変わっている

これを手で写すと、必ず間違えます。そこで、PDFの形に合わせて取り出し方を変えました。

### 縦書き・多列の表：`pdftotext -bbox` で座標から列を決める

`pdftotext -layout` は、多列の表だと列がずれます。`-bbox` を使うと、1文字（1単語）ごとに座標が取れます。**x座標で列を決めれば、目で見て写すより正確です。**

```bash
pdftotext -bbox input.pdf out.html
```

```python
# 単語ごとの (xMin, yMin, 文字) を読み、x座標の範囲で列に振り分ける
# 列の境界は、見出しの単語の座標から決める
```

【👤確認: 実際のコードの抜粋を ops/baselines/ehime-r9/ から短く引用するか】

愛媛県の令和9年度の資料をこの方法で取り出したとき、**前年度（令和8年度）のデータで「作文」と「小論文」の列を取り違えていた**ことも見つかりました。目で写していたときには、気づけなかった間違いです。

### 罫線のある表：PyMuPDF の `find_tables()`

罫線で区切られた表なら、PyMuPDF の `find_tables()` がいちばん速いです。

```python
import fitz  # PyMuPDF

doc = fitz.open("input.pdf")
for page in doc:
    for table in page.find_tables():
        rows = table.extract()
```

## AIに写させると、どこで間違えるか

AIにPDFを読ませて数字を写させると、ほとんどは合っています。**でも、数字の1〜2文字の違いは、ほぼ確実に見落とします。** 「3.5」と「3.6」、「120」と「128」のような違いです。人が目で確かめても、同じところを見落とします。

そこで、**写した結果とPDFを、機械で照らし合わせる**ことにしました。

1. PDFから、ページごとに文字の集合を取り出す（`-bbox` の結果）
2. 写したデータに出てくる数字・文字を、ページごとに集める
3. **データにあるのにPDFのそのページに無い文字**を一覧にする

東京都の資料（別表16）でこれをやったところ、**目視で確認済みだったデータから9件の食い違い**が見つかりました。

もう一つ、実際にあった失敗です。北海道のデータで、数字は正しいのに、**出典のURLだけ、同じ報告書の別のPDF**（集計版と学校別版）を指していました。それからは、**「実際に読んだPDF」と「出典として書くURL」が同じものか**を、毎回確かめています。

## 検証をテストに固定する

人が気をつけるだけでは、いつか崩れます。なので、ルールをテストにしました。

- 各県のデータに出典URLと取得日があるか
- 計算結果が、教育委員会の資料に載っている計算例と一致するか（例: 文部科学省の資料にある「学習成績の状況」の計算例 120÷31＝3.87→3.9 を、そのまま検算できる形にしています）
- 47県分のページが、県名を入れ替えただけの似た文章になっていないか
- 計算APIが、氏名や学校名を受け取る項目を持っていないか

いまはテストが **553ファイル・8,392件** あります（2026-09-24時点）。

## 学校ページ約3,400枚を Cloudflare Workers で配る

構成は Next.js（App Router）を OpenNext で Cloudflare Workers に載せています。公立高校の学校ページが約3,400枚あり、すべて静的に生成しています。

ハマったところを1つ。**動的ルート（`[schoolCode]` など）は `generateStaticParams` を必ず書く**こと。書かないと、Workers 上でエラー（Error 1102）になりました。逆に `dynamicParams = false` を付けると、生成されなかったページが404になります。

## おわりに

半年やってみて分かったのは、**正確さは、書いたコードの量ではなく、捨てた数字と、照らし合わせた回数で決まる**ということでした。

もし「この県のこの数字、資料と違う」というのを見つけたら、教えてもらえると本当に助かります。
