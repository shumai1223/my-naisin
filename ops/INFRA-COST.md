# インフラ費用の監視 — Cloudflare 請求が $5.50 → $104.76 に跳ねた件

- 記録: 2026-08-14
- **原因は loop の push 頻度。設計判断の誤りであり、外部要因ではない。**

---

## 実測（👤がダッシュボードで確認した請求内訳・Invoice IN-74884235）

| 項目 | 期間 | 数量 | 単価 | 金額 |
|---|---|---|---|---|
| Workers CPU ms | 7/11–8/10 | 17,620,296 | $0.02 / 1M | **$0.36** |
| **Worker Build Minutes**（月6,000分込み） | 7/11–8/10 | **17,974分** | $0.005 / 分 | **$89.87** |
| Workers Paid | 8/11–9/10 | 1 | $5.00 | $5.00 |
| | | | 税10% | |
| **合計** | | | | **$104.76** |

**Build Minutes が請求の 86%。** Workers CPU（＝実ユーザーのアクセス）は **$0.36 しかかかっていない。**
**サイトの運用コストではなく、開発プロセスのコストである。**

| 2026-07-10 | $11.51 | my-shingaku.com ドメイン登録 |

## 原因

**`loop-start.bat` が「green なら毎回即 push」で回っており、push 1回ごとに Workers Build が起動する。**

実測:

| | 値 |
|---|---|
| 過去30日のコミット数 | **2,667件**（89件/日） |
| 過去14日 | 1,886件（135件/日） |
| **うち `src/` `public/` 設定ファイルに触れないもの** | **46.4%**（＝デプロイ不要） |
| 1ビルドあたりの所要 | 17,974 ÷ 2,667 ≈ **6.7分** |
| 無料枠 | 月 **6,000分** ＝ 約895ビルド ＝ **30ビルド/日** |

**現状89ビルド/日は、無料枠の約3倍。**

### ⚠️ これは自分（対話セッション）の判断ミスが原因

`memory/fable5-loop-protocol` にこう書いてある:

> **2026-07-11: Workers Paid化（3MB→10MB上限）によりpushバッチ制限を廃止・green毎回即push**

「Workers Paid にしたから制限は不要」と判断した記録。**当時ビルド課金を計算に入れていなかった。**
その判断が、収益¥0の状況で**月$100弱の固定費**を生んでいる。

---

## 対策（この順で効く）

### ① Build watch paths を設定する【👤・最も効く】

Cloudflare ダッシュボード → Workers & Pages → my-naishin → **Settings → Builds → Build watch paths**

**Include にこれだけを指定する:**

```
src/*
public/*
package.json
wrangler.jsonc
next.config.ts
open-next.config.ts
```

→ `docs/` `ops/` `data/` `memory` のみの変更ではビルドが走らなくなる。**実測で46.4%削減。**

⚠️ **my-shingaku 側にも同じ設定が要る。**

### ② loop の push 方針を変える【loop・`ops/LOOP_CONTRACT.md` に記載済み】

- **`src/` を触った変更は従来どおり即 push**（デプロイが要るため）
- **`docs/` `ops/` `data/` のみの変更は、まとめて1日数回 push**

①と併用すれば **89ビルド/日 → 20〜30ビルド/日** になり、**無料枠6,000分の中に収まる**。

### ③ 毎月の確認を T-R1 に入れる【loop】

**月次 M-5 として追加**: Cloudflare の請求額と Build Minutes を確認し、
`docs/worklog/` に記録する。**6,000分を超えていたら報告する。**
→ 今回は「気づいたのが👤」だった。**誰も見ていなかったから3か月分の請求で初めて表面化した。**

## この記録の意味

**Workers CPU が $0.36 ということは、サイトそのものはほぼタダで動いている。**
費用は全部「開発の回し方」から出ている。**節約すべきはインフラではなく、自分たちの回し方。**

そして——**loop の生産性（1日89コミット）には、これまで見えていなかった単価があった。**
今後「loop をもっと速く回す」という判断をするときは、**ビルド分数も一緒に見ること。**
